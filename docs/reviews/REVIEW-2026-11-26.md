# Часть 1. Код: безопасность и корректность

**Критических проблем не найдено.** Ядро безопасности в хорошем состоянии:
TLS-изоляция по §1 соблюдена, санитайзер корректно снимает CSI/OSC/ESC/C1
(включая вложенные случаи), пароль нигде не светится, редиректы на чужой хост
и https→http запрещены, весь EWS-текст в UI идёт через `Sanitize` +
`tview.Escape`.

# Часть 2. Агентная инфраструктура (docs/, .opencode/, scripts/, AGENTS.md)

**Общий вердикт:** система зрелая и дисциплинированная — правила рождены из
измерений (`token-report.py`, статистика сессий в AI-AGENT-PRACTICES §2), а
не из теории. Критических дыр нет; найденное — в основном рассинхрон
документов с реальностью.

## Что сделано сильно (стоит подсмотреть)

- **`docs/CURRENT` как единственный указатель активного плана** + заморозка
  завершённых планов — агент физически не может «дописать» в историю.
- **Исполнимый процесс вместо прозы:** `close-task.sh` сам ставит галочку и
  коммитит журнал/план/handoff, с проверками (ID-формат, лимит 25 строк
  HANDOFF, чистое дерево). Правило «не коммить руками» подкреплено
  инструментом.
- **Тесты-сторожа** (`policy_test.go`): read-only EWS, запрет
  `InsecureSkipVerify`, одобренные зависимости, границы импортов —
  проверяются кодом, а не дисциплиной.
- **`security-reviewer` read-only на уровне permissions** (deny edit/shell),
  запуск по диапазону коммитов, в `/release` — продуманный fallback при
  деградации субагента.
- **Жизненный цикл инвариантов:** HANDOFF «Не трогать» →
  `ARCHITECTURE.md §4` → `// WHY` у кода; у каждого — «Почему / Не делать».
- **Релиз — решение человека:** merge только после явного «да»,
  permission-guarded git-команды как точка подтверждения.
- **`AI-AGENT-PRACTICES.md §13`** — готовый чек-лист переноса практик в
  другой проект.

1. Устранить пункт 1 части 2 (скиллы): единственное место, где инструкция

2. Зафиксировать политику моделей одной строкой в AGENTS.md и привести три
   файла агентов к ней (п. 2–3 части 2).
3. Встроить статику в гейты (п. 4 части 2) — дёшево: две строки в `check.sh`
   и шаг в `release.md`.
4. Мелочи 6–8 — одной правкой, когда будет активный план (по правилам
   проекта — отдельной задачей, не «по пути»).

Для переноса системы в другой проект точка входа —
`docs/AI-AGENT-PRACTICES.md §13` (чек-лист внедрения); минимальный

`PLAN-TEMPLATE.md` + `check.sh` + `close-task.sh`.
