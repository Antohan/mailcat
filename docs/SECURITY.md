# Чек-лист безопасности mailcat

> Это обязательные требования, а не пожелания. Нарушение любого пункта — дефект,
> который надо исправить до коммита. Ревью по этому файлу делает субагент
> security-reviewer на каждом этапе.

## §1. Изоляция TLS-доверия

Требование: корпоративный root-CA доверителен ТОЛЬКО для соединений приложения
к Exchange. Системное хранилище macOS не трогаем.

```go
func newTLSConfig(caPath string) (*tls.Config, error) {
    cfg := &tls.Config{MinVersion: tls.VersionTLS12}
    if caPath != "" {
        pem, err := os.ReadFile(caPath) // сам файл — 0600, см. §6
        if err != nil { return nil, fmt.Errorf("чтение CA: %w", err) }
        pool := x509.NewCertPool()
        if !pool.AppendCertsFromPEM(pem) {
            return nil, errors.New("в файле CA нет валидных сертификатов PEM")
        }
        cfg.RootCAs = pool // заменяет системные корни ДЛЯ ЭТОГО КЛИЕНТА ТОЛЬКО
    } // ca_path пуст → системные корни (публичный сертификат сервера)
    return cfg, nil
}
```

Запрещено:
- `InsecureSkipVerify = true` — нигде и никогда, даже «для отладки»;
- добавление CA в системный/пользовательский Keychain из кода;
- `RootCAs == nil` при заданном `ca_path`.

Ошибки сертификата показывать пользователю с объяснением («сервер представил
сертификат, который не подписан указанным в ca_path корнем»), не предлагая
обход.

## §2. Пароль

- Хранение: macOS Keychain, сервис `mailcat` (`security add-generic-password
  -a <пользователь> -s mailcat -w`). В конфиге поля пароля НЕТ.
- Чтение: `exec.Command("security", "find-generic-password", "-s", "mailcat", "-w")`;
  вывод не логировать, в ошибки не включать.
- В логах и сообщениях UI пароль/токены не появляются; при отладке дампов HTTP
  (флаг клиента Dump) заголовок Authorization маскируется.

## §3. Санитизация терминала

Весь текст из EWS (темы, имена, адреса, тела, календарные поля, имена вложений) —
непроверенный. До передачи в tview — обязательно через `security.Sanitize()`:

Порядок применения (важно — именно такой):
1. escape-последовательности:
   - CSI: `\x1b\[[0-9;?]*[ -/]*[@-~]`
   - OSC (в т.ч. OSC 8 гиперссылки, OSC 52 буфер обмена): `\x1b\][^\x07\x1b]*(?:\x07|\x1b\\)?`
   - двухсимвольные ESC-команды: `\x1b[@-Z\\-_]`
2. прочие управляющие: `[\x00-\x08\x0b\x0c\x0e-\x1f\x7f\x80-\x9f]`
   (C0 кроме `\t \n \r`, DEL, C1);
3. `strings.ToValidUTF8(s, "\uFFFD")`.

Дополнительно: в tview-виджеты с включённым dynamic colors непроверенные строки
пропускать через `tview.Escape` (иначе текст `[red]` ломает разметку).

Тест-кейсы (минимум, таблица в `internal/security/sanitize_test.go`):
инъекция `\x1b]8;;http://evil\x1b\\текст\x1b]8;;\x1b\\`; OSC 52 записи буфера;
подмена заголовка окна `\x1b]0;`; C1-символ `\x9b`; битый UTF-8 `\xff\xfe`;
нормальный текст с эмодзи и кириллицей — не искажается.

## §4. Анти-фишинг

Обязательные поведения UI:
1. **Реальный адрес отправителя** показывается всегда (имя — рядом, не вместо);
   домен не входит в `org_domains` и не является поддоменом (суффикс с точкой:
   `sub.corp.ru` — внутренний, `corp.ru.evil.tld` — внешний; список
   приоритетнее прежнего одиночного `org_domain`, пустой список — ничего
   не помечается) → префикс `[ВНЕШН]` цветом.
2. **Ссылки**: полный URL виден до открытия (модал `g` или строка реестра);
   текст ссылки ≠ её адрес → пометка ⚠; открытие — только явным действием.
3. **IDN/punycode**: хост содержит `xn--` или не-ASCII → показать punycode-форму
   и флаг (использовать `golang.org/x/net/idna`, не самодельный punycode).
4. **Вложения**: опасные расширения (см. PLAN.md этап 3) → предупреждение
   перед открытием; вложение открывается только после сохранения на диск
   (никаких `open` по URL).
5. **Remote-контент**: из HTML ничего не загружается (html2text оффлайн);
   никаких http-запросов, кроме клиента EWS к сконфигурированному серверу.
   Это свойство зафиксировать тестом (TESTING.md §2).

## §5. Вложения на диске

- Каталог сохранения: `~/Downloads/mailcat/` (или `$TMPDIR/mailcat/` для
  «открыть временно»), права 0700; создавать при старте.
- Имя файла: `filepath.Base` + фильтр символов `[A-Za-z0-9._ -]` (остальное — `_`),
  длина ≤ 200; конфликт имён — суффикс `(1)`, `(2)`…
- Лимит: `ContentLength` вложения против `max_attachment_mb` — проверка ДО
  скачивания; превышение — отказ с сообщением.
- Временные копии удаляются при выходе (этап 5).

## §6. Файлы и права

- `config.toml`, файл CA: права 0600; каталог `~/.config/mailcat/` — 0700.
  Приложение проверяет и предупреждает, если права шире.
- Лог: `~/.local/state/mailcat/mailcat.log` — без секретов (§2).

## §7. Сеть

- Только `https://` к адресу из конфига; редиректы на другие хосты запрещить
  (`http.Client{CheckRedirect: ...}` — отклонять смену хоста).
- Таймауты: общий на запрос 30с; GetAttachment — 5 минут на большие вложения.
- `doctor` не выполняет write-операций; только перечисленные в EWS-REFERENCE.md.

## §8. Чего в проекте нет (и не должно появиться)

- Выполнения скриптов/макросов из писем; рендера HTML в браузерном движке;
- отправки/пересылки/удаления чего-либо (read-only whitelist операций);
- автозапуска вложений; автоматического открытия ссылок без явного действия.

## §9. Уведомления (osascript)

Текст писем попадает в `osascript -e 'display notification …'` — это
командная строка, инъекции недопустимы:

- Заголовок и тело уведомления — только после `security.Sanitize()` (§3);
- AppleScript-экранирование: `"` → `\"`, `\` → `\\`, перевод строки → пробел;
  функция живёт рядом с `platform.Notify` и покрывается таблицей тестов
  (кейсы с кавычками, бэкслэшами, `\n`, пустой строкой);
- `sound` — только имя системного звука (`"default"`), не пользовательская строка;
- `show_subject = false` — режим приватности: тема в уведомлении не
  используется вообще (даже внутри escape-функции);
- Ошибки выполнения osascript логируются, но не прерывают TUI и не
  показываются как уведомления.
