## Журнал решений (CHANGELOG.md) — обязательное правило итерации

После каждой завершённой задачи агент дописывает запись в НАЧАЛО
`CHANGELOG.md` (корень репозитория; файл уже существует):

```markdown
## 2026-11-21 · iter3:RD-1 · палитра и семантика цветов
- Сделано: <1–2 фразы>
- Решения: <нестандартный выбор и почему> (или «нет»)
- Отклонения от плана/золотых правил: <что и почему> (или «нет»)
```

- Одна запись на задачу (коммит), 3–5 строк, без содержимого файлов и diff'ов.
- Любое отклонение от плана — обязательно в журнал; существительное отклонение —
  записать и спросить пользователя. Молча менять план запрещено.
- Смысл: по журналу пользователь проверяет, что агент идёт по плану. Это
  дополнение к `// WHY`-комментариям и HANDOFF «Не трогать» (те — для агента,
  этот журнал — для пользователя).

## Цель

Интерфейс выглядит современно и спокойно: светлая палитра без чёрного текста
и визуального шума, единый синий акцент (активные элементы, выделение,
непрочитанные), тонкие разделители вместо тяжёлых рамок, активная панель видна
сразу, плотность списка сохранена. Микро-UX: анимированная загрузка и
обновление списков без сброса выделения.

## Definition of Done (итерация целиком)

- Светлая тема: чёрного текста нет; акцентные цвета — только синий и
  приглушённый красный ошибок; тёмная тема включается конфигом.
- Плотность списка сохранена: на 140×40 в списке видно ≥30 писем.
- Активная панель определяется мгновенно; разделители тонкие; при resize
  100×30 → 220×60 нет наложений и обрезок.
- Проверено в Terminal.app (256 цветов) и VS Code/iTerm2 (truecolor).
- Непрочитанные различимы с первого взгляда (жирный + синий акцент).
- Тесты зелёные; Sanitize/Escape и тесты-сторожа не ослаблены.
- CHANGELOG-запись на каждую задачу; smoke S3–S6 не сломан.

## Правила итерации

- Ветка — `dev`; merge в main — только `/release` после DoD и smoke.
- Одна сессия = одна задача: `/check` → коммит `iter3:RD-N: <сделано>` →
  CHANGELOG → чекбокс → HANDOFF (Дальше = следующая задача).
- Модели: Flash по умолчанию; флагман — по усмотрению на RD-2 (каркас).
- Sanitize + tview.Escape не ослаблять; инвариант HANDOFF «Не трогать»
  (статус-бар UI-9) особенно актуален для RD-6/RD-7.
