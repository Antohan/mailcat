## Журнал решений (CHANGELOG.md) — обязательное правило итерации

После каждой завершённой задачи агент дописывает запись в НАЧАЛО
`CHANGELOG.md` (корень репозитория; создаётся при первой записи):

```markdown
## 2026-11-20 · iter2:UI-2 · колонки списка писем
- Сделано: <1–2 фразы>
- Решения: <нестандартный выбор и почему> (или «нет»)
- Отклонения от плана/золотых правил: <что и почему> (или «нет»)
```

- Одна запись на задачу (коммит), 3–5 строк, без содержимого файлов и diff'ов.
- Любое отклонение от плана — обязательно в журнал; существенное — записать и
  спросить пользователя. Молча менять план запрещено.
- Смысл: по журналу пользователь проверяет, что агент идёт по плану. Это
  дополнение к `// WHY`-комментариям и HANDOFF «Не трогать» (те — для агента,
  этот журнал — для пользователя).

## Цель

Списки и календарь читаются с первого взгляда; длинные URL и статусы ответа
не ломают вёрстку; активная панель и доступные действия очевидны.
(По итогам обкатки на живом сервере, скриншоты 20.11.)

## Definition of Done (итерация целиком)

- Живая сессия: отправители — имена, дата видна в списке, непрочитанные
  различимы; техпапки не мешают
- URL не ломают строки повестки; полный список ссылок — по `g`; статусы
  ответа видны; «сегодня» ≠ «выбранный день»
- Активная панель видна; подсказки статус-бара соответствуют экрану
- `CHANGELOG.md` — запись на каждую задачу; `/check` зелёный; smoke S3–S6
  не сломан

## Правила итерации

- Одна сессия = одна задача: `/check` → коммит `iter2:UI-N: <сделано>` →
  запись в CHANGELOG.md → чекбокс → переписать HANDOFF (Дальше = следующая
  задача итерации).
- Новая задача попадает в план только как спека: затронутые файлы/символы и
  ожидаемое поведение записаны до кодинг-сессии (образец формулировок —
  UI-1…UI-8 выше). Без указателей на код задача стоит исследование-токены в
  каждой сессии, которая её откроет.
- Ветка — `dev`; `main` — релизная и принимает только завершённую итерацию
  одним merge-коммитом по явной просьбе пользователя (не внутри задачной
  сессии).
- Модели: Flash по умолчанию; флагман через `/models` — на усмотрение для
  UI-2 (колонки/ширины) и UI-4 (реестр ссылок).
- Весь новый текст из EWS — через Sanitize + tview.Escape (SECURITY.md §3);
  read-only и инварианты HANDOFF «Не трогать» не нарушать.
