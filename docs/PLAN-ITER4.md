## Журнал решений (CHANGELOG.md) — обязательное правило итерации

После каждой завершённой задачи агент дописывает запись в НАЧАЛО
`CHANGELOG.md`:

```markdown
## 2026-11-27 · iter4:C-1 · санитизация ошибок doctor

- Сделано: <1–2 фразы>
- Решения: <нестандартный выбор и почему> (или «нет»)
- Отклонения от плана/золотых правил: <что и почему> (или «нет»)
```

- Одна запись на задачу (коммит), 3–5 строк.
- Любое отклонение от плана — только через журнал; существенное — записать и
  спросить пользователя. Молча менять план запрещено.
- Релиз тоже получает запись (формат вводит A-3): пройденные smoke по номерам,
  визуальные подтверждения, каждое явное исключение.

Формат релизной записи:

```markdown
## <дата> · Релиз <итерация> · <тема>

- Smoke: S3, S5 — пройдены; S4, S6 — не требуются (по TESTING.md §5).
- Визуальные подтверждения: V-35…V-53 — «ок» пользователя (или: нет).
- Ревью: <from>..<to>, файлов в диапазоне N, проверено M.
- Исключения: <finding + решение пользователя> (или «нет»).
```

## Цель

Устранить подтверждённые замечания двух ревью. В коде: убрать сырой вывод в
`doctor`, научить вложения предупреждать о macOS-типах, сделать конфиг
строгим. В инфраструктуре: привести скилл EWS к справочнику, дать ревьюеру
фактический diff и остановить релиз на `ВАЖНО`, сделать закрытие задачи
безопасным вне `dev`, поставить статику в гейты и сделать среду агента
проверяемой одной командой. Уязвимости стандартной библиотеки и замечания
staticcheck закрыты до старта.

## Правила итерации

- Ветка — `dev`; merge в `main` — только `/release` после DoD и smoke.
- Одна сессия = одна задача: `/stage <ID>` → работа → `/check` → коммит
  `iter4:<ID>: <сделано>` → запись в `CHANGELOG.md` → переписать
  `docs/HANDOFF.md` → `./scripts/close-task.sh <ID>`.
- Новая задача попадает в план только как спека: файлы, символы и ожидаемое
  поведение записаны до кодинг-сессии.
- Ревью безопасности. Задачи A-1…A-4 идут до настройки канала diff (A-3) и
  закрываются без ревью до коммита — их проверит ревью диапазона на релизе.
  Начиная с C-1 каждая security-задача — все `C-*`, `A-5`, `A-6`, `A-8` —
  проходит ревью своего diff до коммита кода, по каналу из A-3.
- Модель — DeepSeek Flash по умолчанию; флагман — только по явному решению
  пользователя. Лимит 160 шагов — предохранитель от зависания; три одинаковые
  неудачи подряд — стоп.
- Весь текст из EWS — через `security.Sanitize`; инварианты санитизации
  (ARCHITECTURE.md §4.2) не ослаблять. `docs/SECURITY.md` правится дважды:
  вступление о сроках ревью — в A-4, остальное — в A-9.
- Экран что-то меняет только в C-4: скриншот до и после — в отчёте задачи.
