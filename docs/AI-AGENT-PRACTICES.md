# Работа с ИИ-агентами: практики mailcat

> Самодостаточный документ: как мы встроили ИИ-агентов (opencode + LLM) в
> разработку Go-проекта и не разорились на токенах. Опыт одной полной итерации
> (от пустого репозитория до рабочего MVP с пост-релизными фиксами на живом
> сервере) плюс настройки второй итерации. Примеры — из mailcat, принципы
> переносимы на любой проект.

## 1. Семь принципов

1. **Спека до сессии.** Задача попадает в план только с указанием затронутых
   файлов/символов и ожидаемого поведения. Исследование, выполненное один раз
   в документе, не повторяется в каждой сессии, которая откроет задачу.
2. **Одна сессия = одна задача.** Сессия получает задачу и возвращает отчёт;
   следующий шаг — новая сессия. Длинный чат перемножает расход контекста.
3. **Контекст — главный расход.** Каждый шаг агента отправляет весь накопленный
   контекст заново. Все правила ниже так или иначе служат его минимизации.
4. **Память сессии — файл, не чат.** Точка входа — маленький handoff-файл,
   а не история переписки.
5. **Инвариант живёт там, где его попробуют нарушить.** Ошибка, найденная
   однажды, фиксируется `// WHY`-комментарием в коде, а не в чужой голове.
6. **Безопасность — whitelist'ом.** Агенту перечислено, что можно; всё остальное
   запрещено по умолчанию.
7. **Модели — по риску.** Дешёвая/быстрая модель по умолчанию; дорогая — точечно,
   там, где цена ошибки высока.

## 2. Документная система (5 файлов)

| Файл | Роль | Ключевое правило |
|---|---|---|
| `AGENTS.md` | Инструкции агента, читаются автоматически | Золотые правила + карта доков «по одному файлу за раз» |
| `HANDOFF.md` | Точка входа каждой сессии | ≤25 строк, **перезаписывается**, не дополняется |
| План итерации | Спеки задач с указателями на код | Завершённый план замораживается как история |
| `CHANGELOG.md` | Журнал решений для человека | Запись на каждую задачу: сделано / решения / отклонения |
| `ARCHITECTURE.md` | §3 — «холодный» список инвариантов | Только то, что пережило свой этап |

**HANDOFF** — центральное звено. Поля: `Сделано` (только хэши коммитов) /
`Дальше` (задача и что именно читать) / `Открыто` (ручные проверки и вопросы
для человека) / `Не трогать` (инварианты этапа). Принцип: **«код — правда,
handoff — навигация»**; при расхождении доверять коду и удалять протухшую
строку, а не чинить её.

**Инварианты — трёхстрочный комментарий в коде** там, где следующий
«упроститель» их сломает:

```go
// WHY: responses are discarded by generation, not by folder name.
// Why: a late reply from the previous folder overwrites the loaded list.
// Not to do: compare folder names — after A→B→A the old reply looks fresh.
```

Плюс одна строка в hot-списке «Не трогать» HANDOFF. В холодный §3 переезжает
только пережившее этап — иначе список разбухает и его перестают читать.

**CHANGELOG** — audit-след для человека: по нему видно, идёт агент по плану
или самодеятельничает. Любое отклонение от плана обязано попасть в запись;
существенное отклонение — записать и спросить. Молча менять план запрещено.

## 3. Дисциплина сессий

- **Одна сессия = одна задача → коммит → отчёт ≤5 строк → стоп.** Агент сам
  объявляет: «задача закрыта, следующая — в новой сессии».
- **Команда входа** (`/stage UI-1`): загружает из плана только нужную задачу —
  не «изучи проект и предложи план».
- **Circuit breaker.** Три неудачи одного теста/ошибки подряд → стоп, отчёт
  (что пробовал, что подозреваю), задача возвращается в handoff с пометкой
  «застряло». Четвёртая попытка почти никогда не чинит, но всегда стоит окно
  лимита. Дублируется жёстким `steps`-лимитом в конфиге агента.
- **Коммит после каждой задачи** — оборванная сессия не теряет работу.
- **Никаких обсуждений в кодинг-сессии.** Десяток сообщений внутри сессии
  перебилливает весь её контекст десять раз. Обсуждения — в отдельной беседе.

## 4. Экономия токенов (правила для агента)

**Чтение — узкое:**
- найти символ `grep`'ом, а не читать файл; файлы >150 строк — через
  offset/limit;
- не открывать `*_test.go`, которые не редактируешь;
- документация — только указанный раздел (`SECURITY.md §3`), не файл целиком;
- при итерациях `go test -run <Test>`, полный сьюит — один раз в `/check`.

**Вывод — короче:**
- пакетные shell-вызовы: одна команда вместо пяти;
- фильтровать вывод (`| tail -20`, `--stat`, `-q`);
- скрипты-гейты молчат на успехе, печатают только провалы;
- запрет пересказа: не выводить содержимое файлов, не пересказывать доки.

**Кэш префикса** (актуально для провайдеров с автокэшированием контекста):
- не редактировать в кодинг-сессии файл, прочитанный ранее в ней — правка
  инвалидирует кэш, и остаток сессии тарифицируется по полной;
- открывать сессии одинаковой последовательностью (HANDOFF первым);
- не вставлять большие тексты в промпты.

**Прочее:**
- агентские файлы — на английском (меньше токенов), пользовательский вывод —
  на языке пользователя;
- сабагенту — указатель, не дамп: «прочитай §5–6 справочника», вердикт ≤10
  строк. Сабагент, читающий всё, дороже самой работы.

## 5. Качество без агента

Чем больше проверяется **вне** модели, тем меньше запросов:

- **Один гейт-скрипт** (`check.sh`: gofmt → vet → build → test), тихий на
  успехе, с обрезанным выводом на провале — агент не читает стены текста;
- **Golden-тесты на протокол**: каждый SOAP/XML-конверт сверяется с эталонной
  фикстурой — схема не может «поплыть» незаметно;
- **Тесты-сторожа**: тест, падающий при нарушении архитектурного правила
  (например, `crypto/tls` разрешён только в одном пакете);
- **Mock-сервер + фикстуры**: интеграционные тесты офлайн; живой сервер —
  только документированные ручные сценарии для человека;
- **Анти-галлюцинационный скилл**: точный справочник протокола как единственный
  источник правды («нет в справочнике — не существует; уточни у человека») +
  скилл-файл с компактными шаблонами.

## 6. Субагенты и модели

- **Роли, а не толпа.** Два субагента: предметный эксперт (XML-схема) и
  ревьюер безопасности. Рутинным задачам сабагенты не нужны вовсе.
- **Модели по риску.** Основной агент — дешёвая Flash-модель; флагман —
  предметному эксперту и точечным сложным задачам (переключение `/models`).
- **Ревьюер на дешёвой модели.** Чек-лист безопасности механический — жёсткие
  пункты перечислены в его промпте, флагман не нужен. Ревью — раз в этап по
  диапазону коммитов (`git diff <from>..<to>`), не на каждую задачу.
- **Ревьюер — read-only**: в конфиге агента `edit` и `shell` запрещены
  permission-правилами.
- **Permissions-список в конфиге**: рутинные команды (`go build/test`,
  `git status/diff/commit`) разрешены автоматически — нет холостых циклов
  одобрения; опасное (`git push`, `rm -rf`, `security`) — запрещено явно.

## 7. Безопасность (примеры золотых правил)

Формулировки из mailcat — как образец для адаптации:

- **Whitelist операций.** Разрешено четыре read-операции протокола; любые
  create/update/delete/send — «навсегда», независимо от задачи.
- **Не отключать проверку TLS.** Никогда, даже «для отладки» — включая
  «временные» флаги в конфиге.
- **Секреты — вне контекста.** Пароль из системного хранилища; в конфиге,
  логах, ошибках и дампах его нет; правка правил безопасности внутри
  кодинг-сессии запрещена.
- **Внешние данные — заражены.** Любой текст из внешнего мира проходит
  санитизацию до попадания в UI; это правило закреплено тестом-сторожем.
- **Ошибки — человеку.** Сетевая ошибка обязана подсказывать вероятную
  бытовую причину («похоже, VPN выключен»), а не сырой stacktrace.

## 8. Привычки человека (не кодом)

- **Тривиальные правки — руками.** Опечатка, переименование, форматирование:
  руками это ноль токенов, агентом — целая сессия. `formatOnSave` + language
  server в редакторе снимают форматирование с повестки.
- **Планирование — вне кодинг-сессий.** Спеки задач и обсуждения пишутся в
  отдельной беседе (или с человеком-ревьюером); кодинг-сессия стартует с
  готовой задачей.
- **Замер вместо гадания.** Раз в несколько дней смотреть расход по сессиям в
  клиенте: одна аномальная сессия обычно объясняет большую часть лимита, и её
  паттерн закрывается одним правилом.
- **Живые проверки — на себе.** Всё, что требует окружения, недоступного
  агенту (VPN, боевой сервер), оформлено короткими ручными сценариями с
  шагами и ожидаемым результатом.

## 9. Чек-лист внедрения в другом проекте

1. `AGENTS.md`: золотые правила (безопасность, зависимости, объём), карта
   доков, токен-дисциплина (§3–4 этого документа).
2. `HANDOFF.md`: завести, следить за ≤25 строками, переписывать после задачи.
3. План итераций: задачи-спеки с указателями на код; завершённые — замораживать.
4. `check.sh`: один тихий гейт; вызывать один раз в конце задачи.
5. `opencode.json` (или аналог): allowlist рутинных команд + deny опасных.
6. Golden-тесты на внешние протоколы + тесты-сторожа на архитектурные правила.
7. Субагенты: максимум два (предметный эксперт на флагмане, ревьюер на Flash,
   read-only); ревью по диапазону коммитов.
8. `CHANGELOG.md`: запись на каждую задачу — ваш инструмент аудита агента.
9. Circuit breaker + `steps`-лимит: остановить застрявшую сессию раньше, чем
   она съест окно.
10. Привычки из §8 — они бесплатны и дают половину эффекта.

## 10. Чего это позволило избежать (честно)

- Пересборка контекста: доки не читаются целиком ни одной сессией;
- Циклов «падающий тест → правка» на десятки витков: circuit breaker + steps;
- Самодеятельности агента: план-спеки + CHANGELOG-аудит + read-only whitelist;
- Скрытых регрессий инвариантов: тесты-сторожа + «Не трогать» + ревью по ним;
- Холостых циклов одобрения: permissions-allowlist.

Единственная системная цена — дисциплина ведения документов (HANDOFF, спеки,
CHANGELOG). Она окупается с первой же застрявшей сессии.
