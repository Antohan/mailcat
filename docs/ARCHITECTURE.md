# Архитектура mailcat

## 1. Обзор

Одно бинарное Go-приложение; TUI на tview; EWS-клиент без внешних EWS-библиотек
(конверты по шаблонам из `docs/EWS-REFERENCE.md`). Всё read-only.

```
cmd/mailcat ── run (TUI) · doctor · folders
      │
      ├─ internal/ui ──────── tview/tcell: экраны почты и календаря, модалы
      ├─ internal/ews ─────── TLS-изоляция, Basic→NTLM, SOAP, операции чтения
      ├─ internal/notify ──── правила уведомлений, фоновый опрос
      ├─ internal/mail ────── доменные модели, HTML→текст, реестр ссылок
      ├─ internal/security ── санитайзер, анти-фишинг, безопасные имена файлов
      ├─ internal/platform ─ open, Keychain, уведомления macOS, лог
      └─ internal/config ──── TOML, дефолты, валидация
```

Поток данных: EWS-ответы анмаршалятся в доменные модели (`internal/mail`) →
любой текст из них проходит санитайзер (`internal/security`) → только потом
попадает в tview.

## 2. Пакеты и границы

| Пакет | Отвечает за | Не делает |
|---|---|---|
| `cmd/mailcat` | вход, подкоманды, парсинг флагов | бизнес-логику |
| `internal/config` | TOML, дефолты, валидация | хранение пароля |
| `internal/ews` | TLS-пул, Basic→NTLM, SOAP, все операции, типизированные ошибки | UI, кэш |
| `internal/mail` | модели Folder/Message/Attachment/Event, HTML→текст, реестр ссылок | сеть |
| `internal/security` | санитайзер, анти-фишинг, безопасные имена файлов | сеть |
| `internal/notify` | правила уведомлений, фоновый watcher-опрос | показ UI, osascript напрямую |
| `internal/ui` | экраны, навигация, модалы ссылок и вложений | прямые вызовы net/http |
| `internal/platform` | `open`, Keychain (exec `security`), уведомления (osascript), slog | логику приложения |

Границы закреплены тестом `TestImportBoundaries` (`internal/security/policy_test.go`):

- `net/http`, `crypto/tls`, `Azure/go-ntlmssp` — только `internal/ews`;
- `os/exec` — только `internal/platform` и `cmd/mailcat`;
- `rivo/tview` — только `internal/ui`.

## 3. Каркас интерфейса (`internal/ui`)

| Файл | Что в нём |
|---|---|
| `app.go` | `App`: страницы `mail`, `calendar`, `details`, `event`, `links`, `attachments`, `confirm`; верхний бар; две строки статуса; колонка чтения письма; индикация фокуса панелей |
| `mail.go` | `mailScreen`: сайдбар папок, список писем, панель чтения; пагинация |
| `calendar.go`, `calendar_agenda.go`, `calendar_grid.go`, `calendar_format.go` | `calendarScreen`, `monthGrid` (сетка месяца), `agendaList` (повестка), `calendarFooter` («Ближайшее»), форматирование |
| `format.go` | всё текстовое представление: строки списка, заголовки, папки, подсказки |
| `panel.go`, `scrollbar.go` | `panelHeader`, `divider`, `scrollbar` |
| `theme.go` | роли цветов, `applyLightTheme`, `applyDarkTheme` |
| `links.go`, `attachments.go` | модалы ссылок и вложений, подтверждение опасного открытия |

Виджеты с собственным `Draw` (`monthGrid`, `agendaList`, `divider`,
`scrollbar`, карточка шапки письма) рисуют сегментами «текст + стиль» через
tcell. В остальных виджетах действуют динамические цвета tview.

## 4. Инварианты

То, что нельзя «упростить», не сломав поведение. Новое решение сначала живёт
одной строкой в `docs/HANDOFF.md` → «Не трогать», пока этап горячий; пережило
этап — переезжает сюда, не пережило — удаляется. Формат записи: **решение.**
Почему: … Не делать: … Полный текст причины — в комментарии `// WHY` у кода.

### 4.1. Сеть и данные

**tview, а не bubbletea.** Почему: трёхпанельный макет, таблицы и модалы — из
коробки; императивная модель проще для генерации и ревью кода. Не делать:
миграцию на другой фреймворк без веской причины.

**Свой EWS-клиент, без библиотек.** Почему: готовые Go-обёртки EWS — брошенные
форки; нужны несколько операций чтения, конверты зафиксированы golden-тестами.
Не делать: типизированные структуры ради одного запроса — конверт по шаблону
из `EWS-REFERENCE.md`.

**Basic → NTLM.** Почему: один RoundTripper сработает и с Basic, и с сервером,
который отвечает 401 + `WWW-Authenticate: NTLM/Negotiate`. Не делать: выбирать
схему по конфигу — её выбирает сервер.

**Изолированное доверие TLS.** Почему: корпоративный CA должен быть доверенным
только для Exchange. `ca_path` задан — пул только из него, не задан — системные
корни. Не делать: `InsecureSkipVerify`, добавление CA в системный Keychain
(SECURITY.md §1).

**Форма запросов подогнана под живой Exchange 2019 (15.2.2562).** Почему:
сервер отвечает 500 ErrorInvalidRequest на `item:IsRead` в AdditionalProperties
FindItem и на `t:BodyType` в ItemShape GetItem; с CalendarView запрещает
SortOrder и Restriction (ErrorInvalidOperation) — порядок задаёт сам сервер.
Не делать: «дополнять» запросы по общей документации EWS без проверки на живом
сервере; справочник — только `EWS-REFERENCE.md`.

**`soap:Fault` разбирается из тела не-200 ответа.** Почему: живой сервер
отдаёт HTTP 500 с кодом ошибки в теле, а один статус скрывал причину. Не
делать: возвращать только статус HTTP.

**Поздний ответ отбрасывается по поколению запроса.** Почему: ответ прежней
папки (`mail.go`, поколение `gen`) или прежнего месяца (`monthStale`)
перезаписал бы уже загруженный список. Не делать: сравнивать имена папок —
после A→B→A старый ответ выглядит свежим.

**Один http.Client на сессию.** Экраны почты и календаря делят `ews.Client`;
общий контекст отменяется при выходе.

**Ленивые вложения.** FindItem (метаданные) → GetItem → GetAttachment только
по действию пользователя, после проверки ContentLength против лимита.

**Описание встречи кэшируется по ItemID (`eventBodies`).** Почему:
`GetEventBody` — сетевой вызов; повторное открытие встречи не ходит в сеть.

**Пароль.** Только Keychain (`security find-generic-password -s mailcat -w`),
читается при старте; в конфиге поля пароля нет.

**Уведомления — опрос, не push.** Горутина `internal/notify` опрашивает
«Входящие» раз в `interval_sec`, помнит верхний ItemID и при новых письмах
вызывает `platform.Notify`. Первый прогон — без уведомлений; VPN пропал —
тихий backoff. EWS-push (Streaming-подписки) отложен: операции вне read-only
whitelist и висящее соединение ради выигрыша в десятки секунд.

### 4.2. Интерфейс

**Цвета — только роли `theme.go`; акцент один.** Почему: тема задаётся явно
(tview по умолчанию красит панели в чёрный — на светлом терминале чёрное на
чёрном); рамка фокуса и выделение строки — один акцент, они различаются
поверхностью. Не делать: сырые `tcell.Color…` в экранах, отдельный цвет на
каждую смысловую группу.

**Две строки статуса.** Почему: подсказки клавиш видны всегда — раньше ошибки
и «Загрузка…» вытесняли их из единственной строки. Подсказки — только
`showHint`, сообщения и ошибки — только `setStatus`; каждая ветка горутины
вызывает `endLoad` ровно один раз. Не делать: совмещённую строку.

**Рамка неактивной панели красится цветом поверхности.** Почему:
`SetBorder(false)` сдвигает содержимое на каждую смену фокуса. Не делать:
выключать рамку.

**Индикация фокуса — в хуке перед отрисовкой, через `HasFocus()`.** Почему:
по событию `SetFocus` вызовов много, один забыт — рамка врёт; `GetFocus()` в
хуке отрисовки берёт тот же мьютекс Application (deadlock). Не делать:
`GetFocus` внутри отрисовки.

**Строки списков обновляются через `SetItemText` в `DrawFunc`.** Почему:
`Clear` теряет позицию курсора и будит `SetchangedFunc`, из-за чего выделение
уезжало со строки. Не делать: пересборку списка через `Clear` при каждом
обновлении.

**Соответствие «строка ↔ элемент» — отдельные маппинги (`itemRows`,
`rowByItem`, `moreIdx`).** Почему: разделители дат и групп папок сдвигают
индексы. Не делать: брать элемент по индексу строки.

**Обрезка по ширине — в `DrawFunc`, не при присвоении текста.** Почему:
ширина панели меняется при resize (username в футере, дата в шапке письма,
тема в строке списка). Не делать: обрезать один раз при `SetText`.

**Горизонтальная прокрутка панели чтения поглощается.** Почему:
`SetWrap(true)` не отключает её в tview — `→` двигает columnOffset и режет
начало строк. Не делать: рассчитывать, что перенос отключает прокрутку.

**Колонка чтения — фиксированной ширины по центру.** Почему: строка на всю
ширину панели неудобочитаема. Ширину пересчитывает `layoutDetails` перед
отрисовкой; на узком терминале — вся ширина минус поля. Не делать:
перестраивать раскладку внутри `DrawFunc` страницы — до следующего кадра её
не изменить.

**Клик по разделителю групп гасится, а не переносится на строку ниже.**
Почему: иначе List вызвал бы `selectFolder` для соседней папки.

**Сетка месяца: одинаковые ячейки, остаток — в поля.** Почему: иначе ячейки
разного размера и числа дней стоят в разных точках. «Сегодня» — цветом и
жирностью, без заливки (заливка читалась как второе выделение); линии — роль
`colorGridLine`. Не делать: отдавать остаток последней колонке или неделе.

**В собственном `Draw` обязателен `Sanitize`, `tview.Escape` не нужен.** В
виджетах с динамическими цветами — `Sanitize` + `tview.Escape` (SECURITY.md
§3).

### 4.3. Файлы

**Имя файла вложения занимается атомарно (`O_CREATE|O_EXCL`).** Почему:
«проверил `os.Stat` — записал потом» оставлял гонку между проверкой и записью.
Не делать: возвращать только путь, а писать затем `os.WriteFile`.

## 5. Реестр ссылок (анти-фишинг)

При рендере тела письма, «Места» и описания встречи:
1. `mail.NewLinkRegistry` извлекает URL (http/https) в реестр `[1..N]`;
2. в тексте URL отображается как `[N] host` (текст ≠ адрес — пометка ⚠);
3. хосты с `xn--`/не-ASCII — флаг IDN и punycode-форма;
4. клавиша `g` — модал со всеми ссылками: на экране списка, в панели чтения,
   в деталях письма и встречи;
5. открытие — только явное действие (Enter в модале): `/usr/bin/open`.

Инварианты разбора (`internal/mail/links.go`):
- `<?` и `>?` в матче автоссылки поглощают скобки `<https://…>` — иначе после
  замены оставались огрызки «<[1] host>»;
- `href` обязан следовать за пробелом — иначе в `<a data-href="трекер"
  href="настоящий">` совпал бы `data-href`, и в реестр попал бы URL трекера.

## 6. Конфигурация

`config.example.toml` в корне репозитория; путь — `~/.config/mailcat/config.toml`.

| Секция / ключ | Что задаёт |
|---|---|
| `server`, `username`, `ca_path` | Exchange и изолированный CA |
| `org_domain`, `org_domains` | внутренние домены для метки `[ВНЕШН]` |
| `page_size`, `max_attachment_mb` | пагинация и лимит вложений |
| `[ui]`: `language`, `theme`, `hidden_folders` | «ru»; `light` (по умолчанию) или `dark`; технические папки вне панели |
| `[notify]`: `enabled`, `interval_sec`, `min_importance`, `only_external`, `senders`, `keywords`, `show_subject`, `sound` | правила уведомлений |
| `[log] file` | лог без секретов |

## 7. Код-стандарты

- Go 1.26; зависимости — по `go.mod`; новая — только из одобренного списка
  (AGENTS.md, правило 6; проверяет `TestDependenciesAreApproved`).
- Ошибки — `fmt.Errorf("...: %w", err)`; контекст первым аргументом.
- Экспортируем только то, что используется снаружи пакета. Никаких глобальных
  мутабельных переменных, кроме синглтона логгера.
- Табличные тесты; фикстуры в `<pkg>/testdata/`; экраны проверяются на
  `tcell.SimulationScreen`.
- Тесты-сторожа (`internal/security/policy_test.go`) падают при нарушении
  механических правил: read-only операции EWS, отсутствие
  `InsecureSkipVerify`, одобренные зависимости, границы импорта, пароль вне
  конфига.
- Комментарии и сообщения об ошибках — на русском, имена кода — английские.
