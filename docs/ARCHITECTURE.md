# Архитектура mailcat

## 1. Обзор

Одно бинарное Go-приложение; TUI на tview; EWS-клиент без внешних EWS-библиотек
(конверты по шаблонам из `docs/EWS-REFERENCE.md`). Всё read-only.

```
┌─────────────────────────── cmd/mailcat ───────────────────────────┐
│  run (TUI)          doctor (диагностика)          folders (smoke) │
└──────┬──────────────────────┬─────────────────────────┬──────────┘
       │                      │                         │
┌──────▼──────────────────────▼─────────────────────────▼──────────┐
│ internal/ui          internal/ews            internal/config     │
│ (tview, экраны       (TLS-изоляция, auth,    (TOML, дефолты)     │
│  Почта/Календарь)     SOAP, FindFolder/                          │
│                       FindItem/GetItem/                           │
│                       GetAttachment/Calendar)                     │
└──────┬──────────────────────┬─────────────────────────┬──────────┘
       │                      │                         │
┌──────▼───────┐   ┌──────────▼─────────┐   ┌───────────▼─────────┐
│ internal/    │   │ internal/mail      │   │ internal/platform   │
│ security     │   │ (модели, HTML→текст│   │ (macOS: open,       │
│ (санитайзер, │   │  enmime при нужде) │   │  Keychain, лог)     │
│  анти-фишинг)│   └────────────────────┘   └─────────────────────┘
└──────────────┘
```

Поток данных: EWS-ответы анмаршалятся в доменные модели (`internal/mail`) →
любой текст из них проходит санитайзер (`internal/security`) → только потом
попадает в tview.

## 2. Пакеты и ответственность

| Пакет | Отвечает за | Не делает |
|---|---|---|
| `cmd/mailcat` | вход, подкоманды, парсинг флагов | бизнес-логику |
| `internal/config` | TOML, дефолты, валидация | хранение пароля |
| `internal/ews` | TLS-пул, Basic→NTLM, SOAP, все операции, типизированные ошибки | UI, кэш |
| `internal/mail` | модели Folder/Message/Attachment/Event, HTML→текст, адреса | сеть |
| `internal/security` | санитайзер, анти-фишинг, безопасные имена файлов | сеть |
| `internal/notify` | правила уведомлений, фоновый watcher-опрос | показ UI, osascript напрямую |
| `internal/ui` | экраны, навигация, реестр ссылок | прямые вызовы net/http |
| `internal/platform` | `open`, Keychain (exec `security`), slog | логику приложения |

## 3. Ключевые решения

**tview, а не bubbletea.** Трёхпанельный макет, таблицы и модалы — из коробки;
императивная модель проще для генерации/ревью кода. tview построен на tcell,
мышь работает из коробки (регионы-ссылки).

**Свой EWS-клиент, без библиотек.** Готовые Go-EWS-обёртки — брошенные форки;
нам нужны 4 операции, конверты фиксируются golden-тестами. encoding/xml:
структуры с тегами вида `XMLName xml.Name \`xml:"http://...messages FindItem"\``.

**Basic → NTLM fallback.** Один RoundTripper: пробуем Basic; на 401 c
`WWW-Authenticate: NTLM/Negotiate` — `ntlmssp.Negotiator`. Выбор логируется.

**Изолированное доверие TLS.** `ca_path` задан → пул только из этого CA;
не задан → системные корни. Системный Keychain не модифицируется никогда
(SECURITY.md §1).

**Ленивые вложения.** FindItem (IdOnly) → список; GetItem — тело + метаданные
вложений; GetAttachment — только по действию пользователя, после проверки
ContentLength против лимита.

**Один http.Client на сессию.** Screen'ы Почта/Календарь делят `ews.Client`;
общий контекст с отменой при выходе.

**Пароль.** Только Keychain (`security find-generic-password -s mailcat -w`),
читается при старте; в конфиге поля пароля нет вообще.

**Состояние UI.** Простые структуры + мьютекс; фоновая догрузка списка —
через `tview.Application.QueueUpdateDraw`. Без сложных канал-архитектур.

**Уведомления — опрос, не push.** Горутина `internal/notify` опрашивает
«Входящие» (`FindItem`, первая страница) раз в `interval_sec`, помнит верхний
ItemId и при появлении новых вызывает `platform.Notify` (osascript → Центр
уведомлений macOS). Первый прогон запоминает состояние без уведомлений; VPN
пропал — тихий backoff. Полноценный EWS-push (Streaming-подписки) осознанно
отложен: новые операции за пределами read-only whitelist и хрупкое висящее
соединение ради выигрыша в десятки секунд.

## 4. Реестр ссылок (анти-фишинг механизм)

При рендере тела письма:
1. Санитайзер извлекает URL (схемы http/https) в реестр `[1..N]`;
2. В тексте URL отображается как `[1] host.tld` (для текста≠адреса — пометка ⚠);
3. Хосты с `xn--`/не-ASCII — флаг IDN и показ punycode-формы;
4. Клавиша `g` — модал со всеми ссылками (полные URL);
5. Открытие — только явное действие (Enter в модале / клик по региону tview):
   `exec open <url>` (macOS). Реестр живёт в рамках одного открытого письма.

Опционально (после MVP): OSC 8 для терминалов с поддержкой — но URL всё равно
показывается явно, открытие остаётся осознанным действием.

## 5. Конфигурация приложения

См. `config.example.toml` в корне репозитория. Путь: `~/.config/mailcat/config.toml`.
Секция `[ui] language = "ru"` — язык интерфейса (MVP: только «ru»).

## 6. Код-стандарты

- Go ≥ 1.23; ошибки — `fmt.Errorf("...: %w", err)`; контекст первым аргументом.
- Экспортируем только то, что используется снаружи пакета.
- Никаких глобальных мутабельных переменных кроме синглтона логгера.
- Табличные тесты; фикстуры в `<pkg>/testdata/`.
- Комментарии и сообщения об ошибках — на русском, имена кода — англ.
