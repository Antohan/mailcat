# План разработки mailcat

Read-only клиент к корпоративному on-prem Exchange (почта + календарь), Go + TUI.
План разбит на этапы; каждый этап завершается критериями готовности (Definition of Done).
Работай строго по этапам, не перепрыгивая. Перед началом задачи прочитай `AGENTS.md` и
соответствующие разделы `docs/`.

**Порядок обязательных документов:**

| Документ | Когда читать |
|---|---|
| `docs/EWS-REFERENCE.md` | любая задача, где есть EWS/SOAP/XML |
| `docs/SECURITY.md` | любая задача, где есть текст из писем, TLS, пароль, вложения |
| `docs/ARCHITECTURE.md` | любая структурная задача (новый пакет, новый экран) |
| `docs/TESTING.md` | перед написанием тестов |

## Этап 0 — Каркас проекта

**Цель:** пустое приложение, которое запускается, читает конфиг и красиво падает с понятной ошибкой.

Задачи:
- [ ] `go mod init` (модуль `mailcat`), Go ≥ 1.23
- [ ] `cmd/mailcat/main.go` — вход, подкоманды: `mailcat run` (TUI), `mailcat doctor` (диагностика), `mailcat folders` (список папок в stdout — дымовый тест EWS)
- [ ] `internal/config` — загрузка TOML из `~/.config/mailcat/config.toml`, все поля со значениями по умолчанию, ошибки на русском; поля — см. `config.example.toml`
- [ ] `internal/platform` — пока только `Open(path string)` (exec `open`) и логирование `slog` в файл `~/.local/state/mailcat/mailcat.log` (в TUI лог не пишем)

**DoD этапа 0:**
- `go build ./...` и `go vet ./...` чистые; `gofmt -l .` пусто
- `mailcat run` без конфига печатает человеку-понятную ошибку с путём ожидаемого конфига
- `go test ./...` зелёные (тесты на дефолты конфига)

## Этап 1 — EWS-ядро (без UI)

**Цель:** пакет `internal/ews`, умеющий всё, что нужно для чтения, с тестами на фикстурах.

Задачи:
- [ ] TLS-изоляция (`internal/ews/transport.go`): если в конфиге задан `ca_path` — приватный
      `x509.CertPool` **только** из этого CA, `tls.Config{RootCAs: pool, MinVersion: TLS12}`;
      если не задан — системные корни. `InsecureSkipVerify` запрещён (см. SECURITY.md §1)
- [ ] Аутентификация (`internal/ews/auth.go`): сначала Basic (`req.SetBasicAuth`);
      при 401 c `WWW-Authenticate: NTLM/Negotiate` — ретрай через
      `ntlmssp.Negotiator{RoundTripper: base}` (github.com/Azure/go-ntlmssp)
- [ ] SOAP-инфраструктура (`internal/ews/soap.go`): тип `Client{HTTP *http.Client, URL string}`;
      метод `Do(ctx, envelope any) (response, error)`; конверты строго по шаблонам из
      `docs/EWS-REFERENCE.md`; разбор SOAP-ошибок (`soap:Fault` и `ResponseClass="Error"`)
      в типизированные ошибки с кодами (`ErrorAccessDenied`, `ErrorItemNotFound`, …)
- [ ] `FindFolder` — список папок начиная с `msgfolderroot` (Traversal=Shallow)
- [ ] `FindItem` — постранично: `IndexedPageItemView`, сортировка по `item:DateTimeReceived`
      Descending, курсор пагинации из `IndexedPagingOffset` + `IncludesLastItemInRange`
- [ ] `GetItem` — чтение письма: `BodyType="Best"`, `item:TextBody`, список вложений
      (`t:Attachments/t:FileAttachment`: AttachmentId, Name, ContentType, ContentLength)
- [ ] `GetAttachment` — скачивание одного вложения по AttachmentId (base64 `t:Content`)
- [ ] `FindItem + CalendarView` — встречи за диапазон дат из папки `calendar`
- [ ] `internal/mail` — доменные модели: `Folder`, `MessageSummary`, `Message`, `Attachment`,
      `Event`; HTML→текст через `github.com/k3a/html2text`; разбор адресов `mail.Address`
- [ ] Тесты: golden-файлы XML в `internal/ews/testdata/` (запрос и ответ на каждую операцию),
      см. TESTING.md §2; mock-сервер на `httptest` (TESTING.md §3)

**DoD этапа 1:**
- Все операции покрыты golden-тестами (маршалинг запроса + анмаршалинг ответа)
- `go test ./...` зелёные; vet/fmt чистые
- Дымовый тест на живом сервере (вручную, VPN включён): `mailcat folders` печатает список
  папок; `mailcat doctor` проходит все шаги (TESTING.md §5)
- Ни одного `interface{}`-хака в публичном API; ошибки обёрнуты `%w`

## Этап 2 — TUI почты

**Цель:** рабочий трёхпанельный интерфейс чтения почты.

Задачи:
- [ ] `internal/ui/app.go` — инициализация `tview.Application`, переключение экранов
      Почта (`1`) ↔ Календарь (`2` — заглушка до этапа 4), выход `q`/`Ctrl-C`
- [ ] Экран почты: Flex[ папки 20% | список 40% | просмотр 40% ]
- [ ] Панель папок: список из `FindFolder`, счётчик непрочитанных, выбор стрелками
- [ ] Панель списка: колонки `[ВНЕШН]`, отправитель (реальный адрес, не только имя),
      тема, дата; непрочитанные выделены цветом; пагинация при достижении конца
  (`u` — обновить)
- [ ] Панель просмотра: при выборе письма — `GetItem`, показ заголовков (От/Кому/Дата),
      тела (текст, HTML уже сконвертирован); «Загрузка…» при подтягивании
- [ ] Экран деталей письма (модал): все заголовки, полный текст, список вложений
- [ ] Статусная строка: контекстные подсказки клавиш (на русском)

**DoD этапа 2:**
- Навигация: `↑/↓` по списку, `Enter` — детали, `←/→` или `Tab` — между панелями, `u` — обновить
- На живом сервере: чтение реальных писем из «Входящих» и вложенных папок
- Санитайзер включён для ЛЮБОГО текста из EWS (SECURITY.md §3) — до передачи в tview
- Скриншот-сценарий из TESTING.md §4 проходит вручную

## Этап 3 — Вложения, ссылки, анти-фишинг

**Цель:** безопасная работа с вложениями и ссылками.

Задачи:
- [ ] `internal/security/sanitize.go` — стриппер терминальных escape-последовательностей
      и управляющих символов (точные правила и regex — SECURITY.md §3); применяется на
      границе UI ко ВСЕМУ непроверенному тексту
- [ ] tview-инъекции: все непроверенные строки через `tview.Escape` при включённых
      dynamic colors
- [ ] Реестр ссылок: при рендере тела все URL нумеруются `[1]`, `[2]`; в теле выводится
      и текст ссылки, и реальный хост; клавиша `g` — модал со списком ссылок (полные URL);
      открытие — только явным действием (клик по региону/Enter в модале), через `open`
- [ ] Анти-фишинг (`internal/security/phishing.go`):
  - [ ] метка `[ВНЕШН]` — домен отправителя ≠ `org_domain` из конфига
  - [ ] подсветка punycode/IDN-хостов (`xn--`, не-ASCII хосты) — `golang.org/x/net/idna`
  - [ ] флаг «текст ссылки ≠ её адрес»
  - [ ] опасные расширения вложений (`.exe .js .vbs .ps1 .bat .cmd .lnk .hta .scr .jar .msi .docm .xlsm`) — предупреждение перед открытием
- [ ] Вложения: клавиша `v` — модал вложений; `s` — сохранить в `~/Downloads/mailcat/`,
      `o` — сохранить во временную директорию и открыть системным приложением; лимит
      размера `max_attachment_mb` (по `ContentLength`, проверка перед скачиванием);
      безопасное имя файла (`filepath.Base`, фильтрация символов — SECURITY.md §5)
- [ ] Remote-контент: в HTML→текст ничего не загружается (проверить, что html2text не
      ходит в сеть — он не ходит; просто зафиксировать тестом отсутствие HTTP-вызовов
      вне клиента EWS)

**DoD этапа 3:**
- Юнит-тесты санитайзера: кейсы из SECURITY.md §3 (CSI, OSC 8/52, title-инъекция, C1, invalid UTF-8)
- Юнит-тесты phishing-проверок (таблицы: punycode-домен, кириллический look-alike, внешний отправитель)
- Вложение PDF: `o` открывает Preview; `.exe`-имя — предупреждение
- Ссылка с текстом «Сбербанк» на левый домен — подсвечена и показан реальный хост

## Этап 4 — Календарь

**Цель:** просмотр рабочего календаря.

Задачи:
- [ ] `internal/ews/calendar.go` — `FindItem + CalendarView` за месяц (уже сделано в этапе 1
  как операция; здесь — «месячная загрузка» с кэшем в памяти на смену экрана)
- [ ] Экран календаря: Flex[ месяц-сетка 55% | повестка дня 45% ]
- [ ] Месячная сетка: дни с событиями отмечены; `[17]` — выбранный день; `←/→/↑/↓` —
      выбор дня, `Ctrl-←/→` или `n/p` — смена месяца
- [ ] Повестка выбранного дня: время, тема, место; повторяющиеся встречи раскрыты
  сервером (CalendarView)
- [ ] Детали встречи (Enter): организатор, участники (Required/Optional), ваш статус
  (`MyResponseType`: принято/под вопросом/нет ответа), ссылки на созвон — через тот же
  реестр ссылок
- [ ] Анти-фишинг и санитайзер применяются к полям встреч так же, как к письмам

**DoD этапа 4:**
- На живом сервере: месяц отображается, повторяющийся еженедельный синк стоит на всех
  своих датах
- Детали встречи показывают статус ответа
- Переключение Почта↔Календарь не роняет сессию EWS (переиспользуем один Client)

## Этап 5 — Полировка и запуск в эксплуатацию

**Цель:** приложение, которым можно пользоваться ежедневно.

Задачи:
- [ ] Пароль из Keychain: чтение `security find-generic-password -s mailcat -w`;
      если записи нет — приглашение при первом запуске + предложение сохранить
      (`security add-generic-password -a <user> -s mailcat -w`)
- [ ] `mailcat doctor` — пошаговая диагностика с человеко-понятными выводами:
      1) TCP-доступность сервера (иначе: «похоже, VPN выключен»); 2) TLS-рукопожатие с
      изолированным пулом (иначе: объяснение про ca_path); 3) аутентификация; 4) FindFolder
- [ ] Обработка разрыва сети/VPN посреди сессии: понятная ошибка, `u` — повтор
- [ ] Очистка временных файлов вложений при выходе
- [ ] Финальный `README.md` проекта: установка (`go build`), настройка (config.toml,
      CA, Keychain), запуск, FAQ (VPN, сертификат, «почему не Mail.app»)
- [ ] Прогон всего чек-листа TESTING.md §5 + SECURITY-ревью силами субагента
      security-reviewer

**DoD этапа 5:**
- Полный ручной сценарий зелёный; security-ревью без критичных замечаний
- `go vet`, `go test`, `gofmt` чистые; бинарник собирается одной командой

## Этап 6 — Уведомления о новых письмах

**Цель:** уведомление в Центре уведомлений macOS о важных новых письмах, пока TUI запущен.

Задачи:
- [ ] `internal/notify` — правила из `[notify]`-секции конфига; функция решения
      «уведомлять ли» для `MessageSummary` (важность ≥ min_importance, отправитель
      из `senders`/`@домен`, ключевые слова темы, only_external) — чистая логика,
      покрывается таблицами тестов
- [ ] `internal/notify/watcher.go` — горутина-наблюдатель: тикер `interval_sec`
      (минимум 30), `FindItem` по «Входящим» (первая страница), сравнение верхних
      ItemId с последним увиденным; **первый прогон — запомнить топ без
      уведомлений** (иначе шквал при старте)
- [ ] `internal/platform` — `Notify(title, body string, sound bool)` через
      `osascript -e 'display notification …'`; AppleScript-экранирование `"`, `\`
      и переводов строк (SECURITY.md §9) — текст писем попадает в команду!
- [ ] Приватность: `show_subject = false` → только «Новое письмо от <имя>»,
      тема не светится на экране блокировки
- [ ] Обновление счётчика непрочитанных папки в UI (`QueueUpdateDraw`)
- [ ] Устойчивость: ошибка сети/VPN → тихий экспоненциальный backoff (до 5 мин),
      уведомления об ошибках НЕ показываются; восстановление → обычный интервал +
      догон пропущенных писем
- [ ] Конфиг: секция `[notify]` (см. `config.example.toml`)

**DoD этапа 6:**
- Юнит-тесты: матчинг правил, AppleScript-экранирование, первый прогон без
  уведомлений, backoff-логика
- Живой сервер (S8 в TESTING.md §5): новое письмо → уведомление со звуком;
  письмо из отфильтрованной рассылки → тишина; `show_subject=false` скрывает тему;
  выключение VPN посреди работы → нет спама, включение → продолжение опроса
- `notify.enabled = false` полностью выключает watcher (нет таймеров и запросов)

## Общие правила для всех этапов

1. **Read-only неизменен:** в коде не появляется ни одной EWS-операции вне
   `FindFolder`, `FindItem` (+CalendarView), `GetItem`, `GetAttachment`, `ResolveNames` (если
   понадобится для doctor). Увидел `CreateItem`/`UpdateItem`/`SendItem`/`DeleteItem` — стоп.
2. После каждой задачи: `/check` (gofmt → vet → build → test).
3. Коммит после каждого пункта DoD этапа, сообщение вида `stage1: pagination cursor`.
4. Новая зависимость — только из одобренного списка (AGENTS.md); что-то иное — сначала
   обсуди с пользователем.
5. Не реализовывай «на будущее»: MVP-объём зафиксирован этим планом.
