# Стратегия тестирования mailcat

## 1. Принцип

- Юнит-тесты на всю логику без сети: санитайзер, анти-фишинг, конфиг, пагинация,
  XML-кодеки.
- Golden-тесты на каждый SOAP-конверт: захардкоженный XML-ответ сервера →
  анмаршалинг → ожидаемые структуры; и наоборот — маршалинг запроса → сравнение
  с эталоном (нормализованным через `xml.MarshalIndent` — не по строкам сырого
  текста).
- Живой сервер — только ручные smoke-сценарии (§5), автоматом не покрываем.

## 2. Юнит-тесты (обязательный минимум)

| Пакет | Что тестируем |
|---|---|
| `internal/security` | таблицы кейсов санитайзера (SECURITY.md §3), IDN/punycode, `[ВНЕШН]`, текст≠адрес, безопасные имена файлов (path traversal `../../x`, пустое имя, длинное имя, unicode) |
| `internal/config` | дефолты, загрузка примера, невалидный TOML → понятная ошибка |
| `internal/ews` | пагинация (Offset=IndexedPagingOffset, стоп по IncludesLastItemInRange), типизированные ошибки (ResponseClass=Error, SOAP-fault, HTTP 401→NTLM-флаг), лимит вложения по ContentLength |
| `internal/mail` | HTML→текст (таблицы, ссылки, стили), адреса From/To |
| `internal/ui` | навигация списков на `tcell.NewScreen()` c `SimulationScreen` (если практично; иначе — логика выделения/фокуса выносится в чистые функции и тестируется без терминала) |
| `internal/notify` | матчинг правил (важность/отправители/ключевые слова/ВНЕШН), AppleScript-экранирование (SECURITY.md §9), первый прогон без уведомлений, backoff |

Сетевая изоляция юнит-тестов: тест, который порождает исходящие HTTP-вызовы,
считается дефектом (кроме §3, где сервер — localhost). Фиксируется тестом-сторожем:
`http.DefaultTransport` подменяется на возвращающий ошибку в `TestMain` пакетов
`internal/mail` и `internal/security`.

## 3. Mock-сервер EWS (интеграционные тесты офлайн)

`internal/ews/ewsmock_test.go` (или `internal/ewstest` для переиспользования UI-тестами):
- `httptest.Server` на `https://…` c самоподписанным сертификатом (`httptest.NewTLSServer`);
- обработчики по содержимому запроса: `FindFolder` → фикстура-папки; `FindItem` →
  страница писем (учитывает `Offset` — 2 страницы по 3 письма, чтобы проверить
  пагинацию); `GetItem` → письмо c Body + вложениями; `GetAttachment` → base64-блоб;
  CalendarView → 3 встречи, из них одна `Occurrence`;
- режим `auth: basic|ntlm|denied` — Basic принимает, NTLM просто 401 дважды
  (полный NTLM-handshake не мокаем — юнит-тест на Negotiator не нужен, это
  ответственность библиотеки);
- клиент в тестах собирается с `tls.Config{RootCAs: pool сервера}` — заодно
  проверяем механику приватного пула из SECURITY.md §1.

## 4. Фикстуры

Раскладка: `internal/ews/testdata/`:
```
findfolder_response.xml      finditem_request.xml.golden
finditem_response_p1.xml     finditem_response_p2.xml
getitem_response.xml         getattachment_response.xml
calendar_response.xml        soap_fault.xml
```
Файлы — реальные по структуре шаблоны из EWS-REFERENCE.md с выдуманными данными.
При изменении схемы — обновлять фикстуры осознанно (не генерить из кода, иначе
тест теряет смысл).

## 5. Ручные smoke-сценарии (живой сервер, VPN включён)

Прогонять в конце этапов 1, 2, 4, 5; отмечать в PR/коммите.

**S1 — doctor:** `mailcat doctor` — все 4 шага OK. Отрицательные проверки:
выключить VPN → шаг 1 с подсказкой про VPN; указать неверный ca_path → шаг 2
с объяснением; неверный пароль → шаг 3.

**S2 — folders:** `mailcat folders` — список папок с непрочитанными.

**S3 — чтение:** открыть TUI → Входящие → выбрать письмо → детали → вернуться;
пролистать >50 писем (пагинация); вложенная папка; `u` — обновить.

**S4 — вложения:** PDF → `o` открывает Preview; файл с двойным расширением
`report.pdf.exe` → предупреждение; файл >лимита → отказ.

**S5 — ссылки:** письмо с текстом-обманкой (текст «Сбербанк», URL левый) → ⚠ и
реальный хост; IDN-домен → punycode; модал `g` показывает полные URL.

**S6 — календарь:** текущий месяц; повторяющаяся встреча на всех датах; детали
показывают MyResponseType.

**S7 — устойчивость:** посреди сессии выключить VPN → понятная ошибка, `u`
восстанавливает после включения.

**S8 — уведомления:** при запущенном TUI прислать себе письмо → уведомление
Центра уведомлений со звуком (тема скрыта при `show_subject = false`); письмо
под фильтр `senders`/`keywords` не попадает → уведомления нет; выключить VPN →
тихий ретрай без спама уведомлениями, включить → опрос продолжился;
`notify.enabled = false` → watcher не работает вовсе.

## 6. Статический контроль

`/check` (команда opencode) = `gofmt -l .` пусто → `go vet ./...` →
`go build ./...` → `go test ./...`. Перед коммитом — обязательно.
Дополнительно (вручную, по желанию): `govulncheck ./...` на этапе 5.
